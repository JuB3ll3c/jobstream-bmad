# Project Context for AI Agents

_This file contains critical rules and patterns that AI agents must follow when implementing code in this project. Focus on unobvious details that agents might otherwise miss._

---

## Technology Stack & Versions

- **Java 25** + **Spring Boot 4.1.0** (Maven multi-module)
- **jobstream-api** (:8081) — Spring WebMVC + JPA/Hibernate
- **ai-analyzer-service** (:8082) — Spring WebFlux + R2DBC
- **Apache Kafka 4.3.1** — topics `analysis.request`, `cover-letter.request`, `*.DLT`
- **PostgreSQL 18** — shared DB, isolated per-service table ownership (AD-2)
- **Redis 8.2.x** — search cache (TTL 30 min, AD-7)
- **Angular 22** + Tailwind CSS (light theme V1)
- **Docker Compose** — postgres, redis, kafka, both services, frontend
- **OpenAPI** — shared contract between services

**Critical version constraints:**
- Never change stack versions — Spring Boot 4.1.0 requires Java ≥ 21 (Java 25 OK).
- Cross-service communication goes through Kafka, **never** direct REST (AD-1).

## Critical Implementation Rules

### Language-Specific Rules

**Java 25 (backend, both services)**
- **SOLID** principles mandatory: the use cases (`application` layer) depend only on ports (dependency inversion, AD-10); one responsibility per class; open/closed via adapter polymorphism.
- Adapters isolate external systems: WebClient (JSearch/Adzuna/OpenAI), Kafka, JPA/R2DBC, Redis.
- DTOs are **generated by OpenAPI** (backend: `target/generated-sources`; frontend: OpenAPI Angular generation) — **never written or edited by hand**. The OpenAPI spec is the single source of truth for the contract (backend and frontend).
- Error handling: `ProblemDetail` (RFC 9457), error shape `{ "error": "...", "status": N }`.
- IDs **UUID v4**, dates **ISO-8601 UTC** (`yyyy-MM-dd'T'HH:mm:ss'Z'`).

**TypeScript / Angular 22 (frontend)**
- TypeScript strict mode mandatory (no `any` unless justified).
- Standalone components (Angular 22).
- Reactive state with **Signals** (no hand-rolled RxJS `BehaviorSubject` classes); RxJS limited to external streams (HTTP, SSE).
- No UI library — hand-built components with Tailwind + DESIGN.md tokens.
- Data models generated by OpenAPI (same source of truth as the backend).
- Accessibility: WCAG 2.2 AA, `aria-live` for SSE announcements, `prefers-reduced-motion`.

### Framework-Specific Rules

**Spring Boot 4.1.0**
- **Hexagonal** architecture: `adapter/in` (REST, Kafka consumers) → `application` (use cases) → `port` (interfaces) → `adapter/out` (WebClient, JPA/R2DBC, Redis, Kafka producer).
- **jobstream-api**: WebMVC (blocking REST controllers) + JPA/Hibernate — `saved_jobs`, `cv`.
- **ai-analyzer-service**: WebFlux (reactive) + R2DBC — `analysis_results`, SSE (`GET /api/events`, Flux).
- Kafka consumption with **3× retry + exponential backoff** then DLT (`*.DLT`) — never silently drop (AD-9).
- Secrets only via **environment variables** — nothing hard-coded in `application.yml` (NFR-3).

**Angular 22**
- Feature-based structure: standalone components, services injected via `inject()`.
- Native SSE consumption (EventSource/`fetch` stream) wired to **signals**.
- Reusable UI components (Button, Input, Card, Modal, Toast, Pagination, badges) per DESIGN.md.
- Kanban drag & drop via `@angular/cdk/drag-drop`.

### Testing Rules

- **TDD mandatory**: write the failing (red) test first → implement the minimum → refactor. Each story progresses in red/green cycles (strict TDD for business logic).
- **Backend** — JUnit 5 + AssertJ: unit tests for use cases (mocked ports), adapter tests (WebClient, JPA, R2DBC), integration tests with Testcontainers (PostgreSQL 18, Redis 8.2, Kafka 4.3).
- **Frontend** — Jasmine/Karma (or Vitest if configured): unit tests for standalone components + services; components tested against the signal state.
- **API**: OpenAPI contract tested with MockMvc/WebTestClient per service.
- Test naming: `given_..._when_..._then_...` or Given/When/Then in English.
- Story ACs (Given/When/Then) are the source of acceptance tests — every AC must have a traceable test.

### Code Quality & Style Rules

- **Lint/format**: repo conventions (checkstyle/spotless Maven on the backend; ESLint/Prettier on Angular) — check the existing config before coding.
- **Naming**: singular PascalCase entities (`SavedJob`, `AnalysisResult`); kebab-case plural endpoints (`/api/saved-jobs`); kebab-case topics (`analysis.request`).
- **Organization**: strict hexagonal structure (`adapter/in`, `application`, `domain`, `port`, `adapter/out`) on the backend; feature-based on Angular.
- **Comments**: in English when needed; no trivial comments; code should be self-documenting.
- **No emojis** in code, commit messages, or technical docs.
- **Docs**: English for all technical artifacts and documentation.

### Development Workflow Rules

- **Branch**: `feat/<story-id>` (e.g., `feat/1.3-merged-search`).
- **Commit**: short conventional format (e.g., `feat(api): merge JSearch + Adzuna results`).
- **Story completion check**: green tests + Maven build (`./mvnw verify`) + frontend lint/typecheck — a story is "done" only when everything passes.
- **Secrets**: never committed — environment variables only.
- **Sequence**: TDD per story, in order E1 → E2 → E3 → E4.
- **Language**: commits/technical messages in English.

### Critical Don't-Miss Rules

- **No `IN_PROGRESS` status**: processing state is derived (absence of report / pending SSE). Do not add an intermediate status (FR-5, AD-5); fix the sequence diagram that shows one.
- **No inter-service REST**: jobstream-api and ai-analyzer-service communicate **only** via Kafka (AD-1).
- **No cross-table writes**: each service writes exclusively to its own tables (`saved_jobs`+`cv` = api; `analysis_results` = analyzer) — read-only on the other (AD-2).
- **No UI component library** (Angular Material, PrimeNG, Flowbite…) — hand-built components with Tailwind + DESIGN.md tokens. **Tailwind CSS is the styling base** (utility framework, allowed and required).
- **Kanban**: drag & drop via `@angular/cdk/drag-drop` (first-party library); no custom keyboard navigation.
- **Cover letter requires an analysis report**: if `analysis_results` is missing → reject to DLT, never an orphan generation (AD-4).
- **CV overwrite**: single CV, replace-only (no history in V1).
- **Forward-only transitions** on the kanban: backward moves rejected.
- **Search cache**: TTL 30 min, key = normalized query (do not bypass).
- **Local (Windows) gotchas**: no native `python`/`python3` (use `C:\Users\Julien\AppData\Local\Python\bin\python.exe`); `PYTHONIOENCODING=utf-8` required for scripts; avoid the 📊 emoji in cp1252 console output.
